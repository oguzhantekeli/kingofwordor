# Word frequencies, frozen

`<lang>.tsv.gz`: one line per word, `key<TAB>lowercase<TAB>capitalised`.

- **key** - the dictionary key (`src/core/lang.ts`: accents folded, ñ æ ø å
  and the Turkish letters kept), 3-15 letters
- **lowercase** - times the word was written in lowercase: use
- **capitalised** - times it was written capitalised mid-sentence: names and
  titles. A sentence's first word is ambiguous and not counted.

Only words the language's dictionary accepts are kept: generated by the affix
expansion, or (Dutch and Danish compounds) accepted by real Hunspell 1.7 and
seen in lowercase.

Read by `tools/build-dict.mjs` for three things: which words are everyday
(seen twice or more in lowercase), how a lemma's forms are chosen for
Portuguese and Turkish, and which Turkish words are names (never lowercase,
capitalised mid-sentence three or more times).

## Source and licence

Counted from the sentence exports of [Tatoeba](https://tatoeba.org) - "These
files are released under CC BY 2.0 FR" (tatoeba.org/en/downloads). Only counts
are kept; no sentence is redistributed. Attribution ships in the game's Credits
screen. The exact export files are recorded in `manifest.json` (sha256, size,
sentence count) together with the LibreOffice dictionaries commit.

## Regenerating

Tatoeba re-exports weekly, which is why these are frozen: a dictionary must
rebuild byte for byte, because the server replays rounds against the file the
app shipped.

```sh
npm i --no-save hunspell-asm@4.0.2     # real Hunspell 1.7, WebAssembly
node --max-old-space-size=8000 tools/build-freq.mjs [lang ...]
npm run build:dict                       # then rebuild the dictionaries
```

Regenerating changes the dictionaries: redeploy them to `DICT_URL` together
with the app build that ships them.
